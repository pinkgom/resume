# 포트폴리오 전체 리디자인: 편집 타임라인

작성일: 2026-09-30
브랜치: `redesign/edit-timeline`

## 1. 목적과 독자

이 사이트는 GitHub Pages로 공개되는 안경찬 님의 프로필 페이지다. 누구나 볼 수 있다.
두 가지 일을 한다.

1. 처음 온 방문자에게 이 사람이 누구이고 무엇을 해 왔는지 첫 화면에서 알려 준다.
2. 2002년부터의 프로젝트 전부를 빠짐없이 남기는 커리어 기록 역할을 한다.

성공 기준:

- 프로젝트 23건이 모두 숨김 없이 읽힌다. 상세 내용이 모달 뒤에 있지 않다.
- 개발자 → 아키텍트 → 강사 → PM → AI로 역할이 옮겨 온 흐름이 첫 화면에서 보인다.
- 프로젝트를 추가할 때 `data/portfolio-data.json`만 고치면 된다.
- 방송국에서 시스템을 만들어 온 사람의 기록이라는 점이 화면에서 드러난다.
- 몇 년 뒤에 봐도 낡아 보이지 않는다.

## 2. 현재 상태의 문제

- 파랑→보라 그라디언트, 떠다니는 블러 원, 둥근 카드와 그림자, 섹션마다 페이드인.
  어떤 개발자 포트폴리오에도 쓸 수 있는 모양이라 고유한 이력이 드러나지 않는다.
- Timeline과 Projects가 같은 23건을 두 번 보여 준다.
- 상세 내용이 모달 안에 있어 주소로 가리킬 수 없다.
- Skills의 카테고리 목록은 코드에 손으로 적혀 있어 실제 기록과 어긋날 수 있다.
- Hero 소개 문장이 컴포넌트에 하드코딩되어 있다.

## 3. 디자인 개념

**기록은 글로, 계기는 도표로.** 첫 화면의 타임라인은 영상 편집기의 트랙처럼 정밀한
계기이고, 그 아래 목록은 글로 남긴 기록이다. 서체를 달리해 이 구분을 드러낸다.

대담한 요소는 타임라인 하나다. 나머지는 조용하게 둔다.

## 4. 디자인 토큰

`src/index.css`에 CSS 변수로 정의하고(`:root`와 `.dark`), `tailwind.config.js`에서
이름을 붙여 유틸리티 클래스로 쓴다. 기존 `primary`, `dark.*` 색과 커스텀 애니메이션
정의는 삭제한다.

### 4.1 색

| 토큰 | 라이트 | 다크 | 쓰임 |
|---|---|---|---|
| `paper` (용지) | `#EDF0F3` | `#101A23` | 페이지 배경 |
| `ink` (먹) | `#16212C` | `#E4EAF0` | 본문 글자 |
| `ink-soft` (보조 먹) | `#5A6673` | `#93A1AE` | 기간, 부가 정보 |
| `rule` (눈금) | `#C5CDD6` | `#2B3A47` | 연도 눈금선, 행 구분선 |
| `playhead` (플레이헤드) | `#E23A2E` | `#FF5A4F` | 오늘을 가리키는 세로선에만 사용 |

트랙 색. 방송 컬러바의 색상을 채도를 낮춰 쓴다. 역할을 뜻할 때만 쓴다
(타임라인 클립, 기록 행의 역할 표시, 걸러 보기 상태 표시).

| 토큰 | 트랙 | 라이트 | 다크 |
|---|---|---|---|
| `track-pm` | PM | `#AD7A0A` | `#E0B040` |
| `track-architect` | 아키텍트 | `#1E8E99` | `#4FB8C2` |
| `track-dev` | 개발 | `#4B8F4F` | `#78B87B` |
| `track-ops` | 운영 | `#A8458A` | `#D078B4` |
| `track-teach` | 강의 | `#3D5FB8` | `#7C98E6` |

위 값은 아래 기준으로 측정해 확인한 값이다(PM 라이트는 처음의 `#C9921A`가 2.4:1이라
`#AD7A0A`로 낮췄다). 색을 바꿀 때는 같은 색상(hue) 안에서 명도만 조정하고, 기준은
자동 테스트(`src/tokens.test.js`)로 지킨다.

- 본문 글자 대 배경: 4.5:1 이상
- 클립과 플레이헤드 대 배경: 3:1 이상
- 다섯 트랙 색은 색만으로 구분하지 않는다. 트랙은 행 위치와 글자 레이블로도 구분된다.

### 4.2 서체

Google Fonts에서 불러온다. 기존 Inter, Noto Sans KR은 제거한다.

| 역할 | 서체 | 굵기 |
|---|---|---|
| 이름, 섹션 제목, 프로젝트명 | Hahmlet | 500, 600, 700 |
| 본문, 타임라인, 숫자, UI | IBM Plex Sans KR | 400, 500, 600 |

크기와 행간:

| 용도 | 크기 | 행간 | 서체·굵기 |
|---|---|---|---|
| 이름 | `clamp(2.5rem, 6vw, 4.5rem)` | 1.1 | Hahmlet 700 |
| 섹션 제목 | 1.75rem | 1.3 | Hahmlet 600 |
| 프로젝트명 | 1.25rem | 1.4 | Hahmlet 600 |
| 본문 | 1rem | 1.7 | Plex 400 |
| 작은 글자(기간, 레이블) | 0.875rem | 1.5 | Plex 400/500 |

- 기간, 연도, 횟수는 `font-variant-numeric: tabular-nums`로 세로 정렬한다.
- 본문 한 줄은 68자(`max-w-[68ch]`)를 넘기지 않는다.
- 레이블을 전부 대문자로 쓰지 않는다. 고정폭(모노) 서체는 쓰지 않는다.

### 4.3 형태

- 전부 왼쪽 정렬. 콘텐츠 최대 폭 1200px, 좌우 여백은 모바일 16px, 데스크톱 32px.
- 카드, 그림자, 그라디언트, 배경 블러를 쓰지 않는다.
- 구분은 1px `rule` 선으로만 한다. 선은 목록의 행과 타임라인의 눈금이라는 구조를 나타낸다.
- 모서리 반경: 클립 2px, 썸네일과 버튼 4px. 그 밖에는 0.
- 키보드 포커스는 `ink` 2px 외곽선, 2px 간격으로 항상 보이게 한다.

### 4.4 움직임

- 페이지를 열 때 한 번: 플레이헤드가 축의 시작(2002)에서 오늘 위치까지 1.2초 동안
  이동하고(ease-out), 지나간 자리에 클립이 드러난다. CSS만으로 구현한다.
- `prefers-reduced-motion: reduce`이면 처음부터 완성된 상태로 보여 준다.
- 기록 펼침과 접힘은 즉시 또는 200ms 이내.
- 그 외의 스크롤 등장 효과, 호버 확대, 반복 애니메이션은 없다.

### 5.1 머리 (`Header`)

공개 프로필의 첫인상이다. 방문자가 여기서 이 사람이 누구인지 알 수 있어야 한다.

- 프로필 그림(지름 56px 원), 이름(`name`), 영문 이름(`nameEn`).
- 직함: `personalInfo.title`의 ` / `를 쉼표로 바꿔 한 줄로 표시.
- 소개: `personalInfo.intro` (새 필드, 6.1 참조).
- 이메일과 브런치 링크. 글자 링크이며 아이콘만으로 표시하지 않는다.
- 섹션 이동 링크(기록, 기술, 연락)와 테마 전환 버튼. 상단에 고정하지 않는다.

### 5.2 타임라인 (`CareerTimeline`)

- 가로축은 선형 시간. 시작은 가장 이른 프로젝트 시작 연도의 1월, 끝은 가장 늦은 종료
  연도와 올해 중 늦은 해의 12월.
- 세로로 트랙 5개: PM, 아키텍트, 개발, 운영, 강의. 왼쪽에 트랙 이름.
- 프로젝트는 자기 역할에 해당하는 모든 트랙에 클립으로 나타난다.
  역할이 셋이면 클립도 셋이다.
- 같은 트랙에서 기간이 겹치는 클립은 트랙 안에서 줄을 나눈다(6.2의 `packLanes`).
- 연도 눈금은 매년 선을 긋고 2년마다 숫자를 적는다.
- 플레이헤드: 오늘 날짜(런타임의 `new Date()`) 위치에 세로선 하나. 아래에 "오늘".
- 진행 중인 프로젝트의 클립은 플레이헤드에서 끝난다.
- 종료일이 미래인 프로젝트는 플레이헤드 이후 구간을 빗금(예정)으로 표시한다.
- 클립은 `<a href="#프로젝트id">`다. 누르면 해당 기록이 펼쳐지고 그 위치로 이동한다.
  `aria-label`은 "프로젝트명, 기간, 역할" 형식.
- 클립에 포인터를 올리거나 포커스하면 프로젝트명과 기간을 보여 주고, 같은 프로젝트의
  다른 트랙 클립도 함께 강조한다.
- 트랙 이름은 버튼이다. 누르면 그 트랙으로 기록을 거른다(5.5).
- 걸러 보기 중에는 조건에 맞지 않는 클립을 흐리게 한다.
- 폭이 좁으면 타임라인 영역만 가로로 스크롤한다(최소 폭 960px). 처음 위치는 오른쪽
  끝(최근). 트랙 이름 열은 왼쪽에 고정한다. 페이지 자체는 가로로 스크롤되지 않는다.

### 5.3 기록 (`Ledger`, `LedgerEntry`)

Timeline과 Projects를 합친 단일 목록. JSON 순서(최신순)대로 전부 보여 준다.

접힌 행:

- 기간(고정폭 숫자). 표기는 `2026.07 – 진행 중`, `2024.01 – 2024.12`로 통일한다.
- 프로젝트명(`name`)과 그 아래 작은 글자로 영문명(`nameEn`).
- 역할 표시: 트랙 색 사각형과 트랙 이름.
- 행 전체가 버튼(`aria-expanded`)이다.

펼친 내용(행 바로 아래, 모달 없음):

- 개요: `description` 목록.
- 주요 업무: `tasks` 목록.
- 기술: `techStack`을 쉼표로 나눈 항목. 각 항목은 그 기술로 거르는 버튼.
- 화면: `images`가 있으면 썸네일 줄. 누르면 네이티브 `<dialog>`로 크게 보고, 제목을
  캡션으로 표시하며, 이전·다음으로 넘긴다. Esc로 닫는다. 이미지 로드에 실패하면
  그 썸네일을 숨긴다.
- 링크: `links`가 있으면 글자 링크. 키별 이름은 `blog` "블로그 글", `website`
  "웹사이트", `youtube` "YouTube", `android` "Android 앱", `ios` "iOS 앱".
  `blog`는 문자열 또는 배열이며, 배열이면 "블로그 글 1", "블로그 글 2"로 표시.
  새 탭으로 열고 `rel="noopener noreferrer"`.
- 비어 있는 항목(이미지 없음, 링크 없음)은 제목째 생략한다.

동작:

- 여러 행을 동시에 펼칠 수 있다.
- 주소에 `#project_magic` 같은 해시가 있으면 로드 시와 `hashchange` 시 그 행을 펼치고
  그 위치로 이동한다. 걸러 보기로 그 행이 숨겨져 있으면 걸러 보기를 해제한다.
- 행을 펼칠 때 주소 해시를 그 프로젝트 id로 바꾼다(`history.replaceState`).

### 5.4 기술 (`TechIndex`)

- 전 프로젝트의 `techStack`에서 자동 집계한다. 손으로 적은 카테고리는 없앤다.
- 항목마다 기술명, 사용 프로젝트 수, 사용 연도 범위(처음–마지막)를 표시한다.
- 정렬은 사용 횟수 내림차순, 같으면 이름순. 전부 보여 준다(현재 82개).
- CSS 다단(`columns`)으로 배치한다. 각 항목은 그 기술로 기록을 거르는 버튼이다.

### 5.5 걸러 보기

- 상태는 `App`에 둔다: `{ track: 트랙id | null, tech: 기술명 | null }`.
  둘 다 설정되면 둘 다 만족하는 기록만 보인다.
- 기록 제목 옆에 현재 조건과 건수를 표시한다. 예: "기록 7건, 개발 트랙".
  "전체 보기" 버튼으로 해제한다.
- 트랙 이름이나 기술을 누르면 조건을 설정하고 기록 섹션으로 이동한다.
  같은 것을 다시 누르면 해제한다.
- 결과가 0건이면 "조건에 맞는 기록이 없습니다."와 "전체 보기" 버튼을 보여 준다.

### 5.6 연락 (`Footer`)

- 이메일(`mailto:`), 브런치, 위치. 입력 폼은 없앤다.
- 맨 아래에 저작권 표기 한 줄(연도는 런타임 계산).

### 5.7 메타 정보 (`index.html`)

- `<title>`: "안경찬 | AI Engineer, Project Manager, Software Architect"
- `description`과 `og:description`: 소개 문장(6.1의 `intro`)과 같은 내용.
- `keywords`에 AI 관련 직함 추가.
- `og:image`: 프로필 그림의 절대 주소.
- 폰트 링크를 Hahmlet, IBM Plex Sans KR로 교체.

## 6. 데이터와 로직

### 6.1 데이터

`data/portfolio-data.json`의 `projects` 구조는 바꾸지 않는다.
`personalInfo`에 필드 하나를 추가한다.

```json
"intro": "방송국에서 현장에서 사용되는 시스템을 설계하고 만듭니다. 2002년 통신망 관리 시스템 개발로 시작해 아키텍트와 IT 강사, 프로젝트 관리를 거쳤고, 지금은 방송에 쓰이는 AI 서비스를 연구 개발하고 있습니다."
```

이 문장은 본인이 확정한 문안이다(2026-09-30). 구현 시 글자 그대로 넣는다.

### 6.2 `src/utils/career.js`

순수 함수만 둔다. React에 의존하지 않는다.

`parsePeriod(period, today)`
- 입력 예: `"2026.08 - 진행중"`, `"2024.01 ~ 2024.12"`, `"2026.04 - 2028.12"`.
- 구분자는 `-`, `~`, 엔 대시(`–`) 모두 허용, 앞뒤 공백 허용. `진행중`은 `진행 중`,
  `현재`로 적어도 같다. 월은 한 자리(`2027.1`)도 받는다.
- 반환: `{ start, end, ongoing }`. `start`, `end`는 월 단위 정수(`연도 * 12 + 월 - 1`).
  `end`는 종료 월의 다음 달(배타적). `진행중`이면 `end`는 `today`가 속한 달의 다음 달,
  `ongoing`은 `true`.
- 해석할 수 없으면 `null`.

`roleTracks(role)`
- `role`을 쉼표로 나눠 각 항목을 트랙으로 분류한다(대소문자 무시).

| 트랙 id | 포함하는 단어 |
|---|---|
| `pm` | `Manager`, `Leader` |
| `architect` | `Architect` |
| `dev` | `Developer` |
| `ops` | `DevOps`, `Operator`, `QA`, `Maintenance` |
| `teach` | `Instructor` |

- 반환: `{ tracks, unclassified }`. `tracks`는 중복 없는 트랙 id 배열이며 순서는
  위 표의 순서. `unclassified`는 어느 트랙에도 속하지 않은 역할 문자열 배열.

`packLanes(clips)`
- 한 트랙의 클립 배열(`{ id, start, end }`)을 받아 각 클립에 `lane` 번호를 붙인다.
- 시작 순으로 정렬해, 마지막 클립의 `end`가 새 클립의 `start` 이하인 첫 줄에 넣는다.
  없으면 새 줄을 만든다.
- 반환: `{ clips: [...], laneCount }`.

`buildTechIndex(projects, today)`
- `techStack`을 쉼표로 나누고 앞뒤 공백을 없앤다. 대소문자만 다른 것은 같은 기술로
  보고 처음 나온 표기를 쓴다.
- 반환: `{ name, count, firstYear, lastYear }` 배열. 정렬은 5.4와 같다.
- `firstYear`는 그 기술을 쓴 프로젝트의 가장 이른 시작 연도, `lastYear`는 가장 늦은
  종료 연도다. 종료가 미래이거나 진행 중이면 `today`의 연도로 한다. 기간을 해석하지
  못한 프로젝트는 횟수에만 넣고 연도 계산에서는 뺀다.

### 6.3 예외 처리

- `parsePeriod`가 `null`인 프로젝트: 기록에는 원문 기간으로 표시하고 타임라인에서는
  뺀다. 개발 모드에서 `console.warn`.
- 어느 트랙에도 속하지 않는 프로젝트: 기록에는 나오고 타임라인에서는 뺀다.
  분류되지 않은 역할이 있으면 개발 모드에서 `console.warn`.
- `localStorage` 접근 실패 시 테마는 시스템 설정을 따른다.

## 8. 검증

- `career.js`는 테스트를 먼저 쓰고 구현한다. 최소한 다음을 확인한다.
  - 기간 표기 세 가지가 모두 해석된다. 잘못된 문자열은 `null`.
  - 실제 JSON의 23건이 전부 해석되고, 전부 하나 이상의 트랙에 속하며, 분류되지 않은
    역할이 없다.
  - 겹치는 클립은 다른 줄에, 맞닿은 클립(앞의 끝 = 뒤의 시작)은 같은 줄에 놓인다.
  - 기술 색인에서 대소문자만 다른 항목이 합쳐지고 정렬이 맞다.
- 컴포넌트 동작(행 펼침, 해시로 열기, 걸러 보기, 빈 항목 생략, 테마 전환)은 jsdom
  환경의 테스트로 확인한다.
- `npm test`, `npm run build`가 통과한다.
- 개발 서버에서 라이트/다크, 1280px/390px 폭 네 가지 화면을 캡처해 확인한다.
  390px에서 페이지가 가로로 스크롤되지 않는지 본다.
- 키보드만으로 클립 이동, 행 펼침, 이미지 보기 열고 닫기, 걸러 보기 해제가 되는지 본다.
- 4.1의 대비 기준을 측정한다.
